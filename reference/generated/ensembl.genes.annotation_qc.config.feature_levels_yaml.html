Source: src/python/ensembl/genes/annotation_qc/config/feature_levels.yaml

  1# -----------------------------------------------------------------------------
  2#                       FEATURE LEVEL DEFINITION FILE
  3# -----------------------------------------------------------------------------
  4
  5# AGAT parser (_sp_ prefix scipts) handles the features (1 line = 1 feature where
  6# the feature type is indicated within the 3rd column) only if the feature type is
  7# declared within this file, otherwise it will be skipped.
  8# Features must be linked to one and only one of the 3 available levels: leve1,
  9# level2, level3. It depends is Parent or children are expected by the feature.
 10# Please find more info in the corresponding section below.
 11
 12# Few features (e.g. CDS, UTR) can span multiple lines because are spread over
 13# multiple locations within the genome while representing only one biological
 14# concept. In such case you must also add the information (only if missing) in
 15# the "spread feature "section
 16
 17# Some feature can require extra information. This extra information is added as
 18# follow:
 19# -feature: extra_information
 20# In order to keep the file consistent, when no information is needed we put 1
 21# as default value. This does not have any specific meaning.
 22
 23# ----------------------------------- LEVEL1 -----------------------------------
 24# Level1 features are features without parent.
 25# Level1 features with topfeature or standalone value do not expect children. It means they will not be removed if no sub-feature is linked to it.
 26# Level1 features with standalone value will be sorted in the same way as other features e.g. by position in the sequence
 27# Level1 features with topfeature value will not be sorted in the same way as other features e.g. all topfeature will be printed first in the sequence
